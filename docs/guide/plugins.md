## 设计理念：插件 = MCP + 扩展

Cage 的核心路线是把有风险的运行外壳（Claude Code、Claude Desktop 与内置浏览器）关在轻量化的本地 Debian 13 隔离环境中，再通过标准 [MCP](https://modelcontextprotocol.io) 插件，让 Claude 安全、受控地使用本机能力。相比直接暴露主机 SSH，每一次越出环境的调用都有清晰的权限声明与用户授权。

在 Cage 中，**插件 = MCP + 扩展**，分别承担两项职责，一个插件可以同时提供两者：

| 形态 | 作用 | 对应清单字段 |
| --- | --- | --- |
| **给 Claude 的能力（MCP）** | 提供标准输入输出的 MCP 工具，让环境里的 Claude 能够操作本机桌面、处理本地文档、调用本机软件或读写环境内服务 | `contributes.mcpServers` |
| **定制 Cage（扩展）** | 在 Cage 侧栏新增独立的沙箱页面，把状态面板、控制台或工作流界面直接融进工作台 | `contributes.views` |

通过开放的插件市场 [cage-plugins](https://github.com/Lee-xeo/cage-plugins)，开源社区可以持续贡献各类 MCP 工具与工作台扩展，而不必挤进 Cage 主仓库的 Issue 列表；Cage 核心团队也能专注于隔离环境、网络与工作台本身的稳定性。

## 主机插件与环境内插件

按运行位置不同，插件分为两种 `kind`：

| 类型 | 运行位置 | 适用场景 | 授权方式 |
| --- | --- | --- | --- |
| **主机插件（`host`）** | 你的电脑（macOS / Windows / Linux） | 需要本机能力：屏幕与键鼠控制、Office 文档读写、Blender 等桌面应用联动、在共享项目目录中运行本机命令 | 运行于你的用户权限，不受隔离保护；默认逐次弹窗确认，可按需开启「始终允许」 |
| **环境内插件（`guest`）** | Cage 内的 Debian 13 环境 | 只在环境内工作：查看系统状态、操作环境内文件、控制环境内 Chromium 浏览器或内部服务 | 未声明越出环境权限时无需弹窗确认 |

> **说明**：本页介绍的是 Cage 侧栏的「插件」与开放插件市场（`cage-plugins`）。如果你在查找多账号之间如何共用 Claude Code 自己的技能、钩子与插件，请见[多账号与额度](accounts.md#共享技能插件钩子和记忆)。

## 从插件市场安装与管理

1. 在工作台左侧栏打开 **插件**，先开启总开关。
2. 切换到 **插件市场**，按分类（桌面控制、开发、系统与状态、网络、文件、效率、示例）浏览或搜索插件。
3. 打开插件详情页，查看功能说明、声明的权限以及基于的上游开源项目信息，点击安装即可。

市场索引与压缩包来自 [cage-plugins](https://github.com/Lee-xeo/cage-plugins)：

- **校验与网络**：应用读取市场索引、下载压缩包并核对 SHA-256，同时检查压缩包大小（解压后不超过 100 MiB、2000 个文件）以及索引权限与插件清单完全一致。读取和下载走电脑自己的网络，遵循系统代理设置。
- **上游开源依赖**：基于开源项目的插件会在详情页「上游项目」展示项目名、版本、许可证和地址。部分插件首次启动时通过 `npx` 或 `uvx` 拉取上游固定版本，需先在本机安装 Node.js 或 [uv](https://docs.astral.sh/uv/)；主机插件启动时会使用与终端相同的 `PATH`。
- **手动安装与调试**：可将插件目录直接放入配置目录的 `plugins/` 下（默认 `~/.claude-cage/plugins/<插件名>/`），再在插件页点击 **重新加载**。环境内插件的文件会在启动与重新加载时同步到环境内的 `~/.local/share/plugins/<插件名>/`。
- **设置与密钥**：插件可以声明需要填写的设置（如服务地址、访问令牌），在详情页的 **设置** 标签中填写。必填项为空时插件显示「需要配置」且不启动，保存后自动启动。密钥用你的 Cage 账户加密保存，保存后不再显示；Cage 锁定时，用到密钥的插件会停止，解锁后自动恢复。详见[插件文档](../plugins.md#设置与密钥)。
- **默认预装与卸载**：Cage 首次初始化时会自动部署官方精选的默认预装插件（`cage-plugin` 插件工坊与 `use-cage` 控制 Cage），记录在配置目录的 `default-plugins.json` 中。默认预装插件可像普通插件一样随时停用或卸载；卸载后更新 Cage 不会强制装回，需要时可在 **插件设置 → 已卸载的默认插件** 中一键恢复。
- **停用与卸载**：每个插件（包括内置的命令插件）都可以单独停用，停用后停止运行且不向 Claude 暴露工具，文件留在原处。卸载或更新插件时，旧目录会移到配置目录的 `plugins-removed/` 下保留，不会直接删除。
- **在 Claude Code 与 Desktop 中显式调用**：已启用的插件统一通过名为 `computer` 的 MCP 服务提供给 Claude Code、默认 Claude Desktop 以及多账号编号 Desktop。每个提供模型工具的插件（以及插件自身声明的 MCP Prompts）都会暴露为斜杠指令：在 Claude Code 中输入 `/mcp__computer__<插件或指令名>`（例如 `/mcp__computer__commands`），或在 Claude Desktop 输入框的 `/` / `+` 菜单中选用 `computer` 下的对应指令，即可显式指定调用该插件的工具。

## 让 Claude 查找并创建插件（`cage-plugin`）

默认预装的 **插件工坊（`cage-plugin`）** 是一个无宿主机越界权限的环境内插件，支持 **先查找现成插件、没有再按需创建** 的完整闭环：

1. 直接对环境内的 Claude 描述需求（例如“帮我读写 Excel 表格”或“帮我写一个查看当前项目构建状态的侧栏面板”）。
2. Claude 会先调用 `search_plugins` 检索插件市场与已安装插件：若已有现成插件，会直接建议你使用或前往插件市场一键安装，避免重复造轮子。
3. 若市场中没有合适插件，Claude 会按中性规范生成脚手架、编写代码，并自动执行清单校验、沙箱页面 CSP 检查以及真实 MCP `initialize` / `tools/list` 冒烟测试。
4. 校验通过后，Claude 提交只读草稿快照（Claude 本身无权写入宿主机插件目录）。你在工作台插件侧栏打开 **待审核草稿**，逐文件查看源码、核对权限与贡献点、选择运行位置（推荐环境内；选本机时强制逐次弹窗确认），点击 **安装并重载** 即可生效。覆盖已有插件时，旧版保留在 `plugins-removed/` 中，且原有「始终允许」授权会被强制撤销。

## 让 Claude 受控调整 Cage 设置（`use-cage`）

默认预装的 **控制 Cage（`use-cage`）** 让环境内的 Claude 可以在严格受控的能力边界内协助调整 Cage 偏好：

- **可查询与调整的安全范围**：读取当前外观、显示偏好、已打开项目与扩展摘要；切换亮暗主题、字号、配色与动效偏好；调整显示密度、12/24 小时制、自动时区/语言、浏览器默认主页等白名单偏好。
- **敏感控制强确认**：启用/停用非核心扩展或重载插件（`workspace_manage_extension`）硬编码禁止「始终允许」，即便该插件已授权「始终允许」，每次调用仍会弹窗由你确认。
- **不可越过的安全边界**：新增宿主机共享目录、修改代理与网络出口规则、更改插件授权状态、账户密码与加密密钥等高危项一律不向该插件开放，只能由你在工作台或宿主机外部 Agent 入口操作。

## 主机授权与安全边界

主机插件以你的系统用户权限运行在电脑上，是否放行由你掌控：

- **显式确认**：调用前弹出系统确认窗口，展示插件名、工具名和参数。可以选择拒绝、只允许这一次，或勾选「始终允许」。确认窗口 2 分钟未响应时自动按拒绝处理。
- **持久化授权与撤销**：「始终允许」按插件记录，覆盖该插件的全部工具（内置命令插件按项目目录记录），重启后依然有效。可在插件详情页的 **授权与权限** 中随时查看、授予或撤销；撤销后立即恢复逐次确认。从市场安装时也可勾选「安装后始终允许」。
- **权限变更保护**：插件更新后，只要声明了你此前未同意的新权限，原有授权会自动失效并重新询问。通过插件页卸载插件时，授权记录会一并清除。
- **超长与不可见参数拦截**：参数超过 4000 字节，或包含控制字符、不可见格式字符时，即使已勾选「始终允许」也会直接拒绝，防止确认窗口无法完整展示调用内容。较长内容应先写入文件，再传递文件路径。
- **页面与模型共用授权**：插件沙箱页面调用工具与 Claude 调用工具共享同一套授权；沙箱页面本身无法联网，也拿不到工作台凭据。
- **跨平台提示**：
  - **Windows**：系统确认窗口提供允许和拒绝两个按钮，「始终允许」需在插件详情页的「授权与权限」中设置（内置命令插件可按已打开的项目分别授权）。
  - **Linux**：弹出系统确认窗口依赖 `zenity` 或 `kdialog`；两者均未安装时，需要确认的主机调用一律拒绝。
- **环境内插件的密钥**：把密钥交给环境内插件时，密钥会离开这台电脑，环境内以同一用户运行的其他程序（包括 Claude）也可能读到。每次保存密钥前都需要你在确认窗口中确认这一风险。
- **个人数据保留**：授权记录保存在配置目录的 `host-grants.json` 中，属于个人数据，升级与重装 Cage 时保留。

## 远程主机中的插件

部署在云端服务器或远程主机上的 Cage 同样支持插件：

- **自动同步到远程**：通过桌面端 SSH 连接并解锁远程主机后，Cage 会自动将本机已安装的兼容插件单向增量同步到远程（跳过不兼容系统及无头服务器无法使用的屏幕/键鼠类插件；不删除远程单独安装的插件，也不同步本机授权和密钥）。
- **审批弹窗回流本机**：远程主机上的 `commands` 和主机插件需要确认时，确认弹窗会在你面前的桌面端弹出并标明远程主机名称；已设为「始终允许」的项目或插件在客户端断开后仍可自动放行。
- **反向共享本机插件**：像 `blender`、`desktop-control` 这类依赖本机桌面的插件，可以在远程工作台「插件设置 → 共享本机插件给当前远程」里按需临时开启。开启后，远程 Claude 调用它们时会经加密隧道回到你本机审批并执行，断开连接后自动收回。

## 在环境中运行其他桌面应用

除了 Claude Desktop，Cage 也能通过插件在环境里运行其他厂商的官方桌面应用，例如 `codex-app`（OpenAI 的 Codex，即 Linux 版 ChatGPT 应用）和 `antigravity-app`（Google 的 Antigravity）。它们和 Claude Desktop 一样在自己的画面中运行，可以复制粘贴、选择项目、上传附件，登录在 Cage 浏览器完成后回到应用。这类插件不做多账号管理，每个应用一份登录。

- **安装与打开**：从插件市场安装插件后，侧栏会出现应用入口。首次打开时点“下载并安装”，Cage 从厂商的官方渠道下载，再点“打开应用”。
- **默认使用最新版本**：插件只写明官方下载渠道，不锁定版本。点应用顶部的“更新应用”，Cage 会关闭应用、安装当时的官方最新版本并重新打开。厂商改变发布方式导致装不上或打不开时，升级插件即可修复。
- **数据保留**：应用的登录、设置和项目保存在环境里。更新、卸载应用或升级插件只处理应用文件，重新安装后继续使用原来的登录。
- **资源**：每个应用都会占用一份内存。环境内存不足时，应用可能被系统关闭；同时运行多个应用前，先在设置中检查计算资源。

## 常见插件示例

可以在[官网插件市场](https://claude-cage.com/plugins/)在线浏览全部插件、权限声明与 SHA-256 校验值，或在 [cage-plugins](https://github.com/Lee-xeo/cage-plugins) 仓库查看源码。代表性插件包括：

- **`desktop-control`**（主机插件）：查看屏幕并控制本机键鼠，声明 `screen` 和 `input` 权限。
- **`blender`**（主机插件）：连接并操作本机正在运行的 Blender（基于 `ahujasid/blender-mcp`）。
- **`local-preview`**（主机插件）：打开本机回环地址的开发预览页并读回标签页标题与地址。
- **`excel-workbooks` / `word-documents` / `powerpoint-slides`**（环境内插件）：无需安装 Office 即可读写表格、文档与演示文稿。
- **`documents-to-markdown`**（环境内插件）：将 PDF、Office、EPUB 与 HTML 文档解析为整洁 Markdown。
- **`browser`**（环境内插件）：控制环境内的 Chromium 浏览网页（基于 `microsoft/playwright-mcp`）。
- **`codex-app` / `antigravity-app`**（环境内插件）：在环境中运行 Codex 或 Antigravity 的官方桌面应用，默认跟随官方最新版本。
- **`system-status`**（环境内插件）：同时提供 MCP 工具与自定义侧栏页面，展示环境处理器、内存与磁盘状态。
- **`clock`**（主机插件）：最小示例插件，适合作为开发模板。

## 开发与上架自己的插件

任何能读写标准输入输出的程序都可以写成 Cage 的 MCP 插件，任何静态 HTML/JS/CSS 页面都可以封装成工作台扩展视图。

- 完整的清单格式（`plugin.json`）、权限列表、沙箱页面 JSON-RPC 协议、工具命名规则（不向模型暴露产品与运行环境名称）以及本地调试方法，见[插件开发规范](https://github.com/Lee-xeo/Claude-Cage/blob/main/docs/plugins.md)。
- 打包脚本、审核要求与提交流程见 [cage-plugins](https://github.com/Lee-xeo/cage-plugins)。发起 PR 时请按仓库 PR 模板填写信息并在描述中附带插件在 Cage 中的真实运行效果图（脱敏后直接拖入 PR 描述框，不打进插件包）。欢迎把你的 MCP 工具和 Cage 扩展页面直接贡献到插件市场。
