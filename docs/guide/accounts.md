## 添加和识别 Claude 账号

启动环境后，在侧栏打开“Claude 账号管理”，点“添加账号”。Linux 环境已导入代理节点时，可以先选本次授权和后续使用的账号出口。点“开始授权”，在浏览器中完成登录。也可以直接从 Desktop 或 Claude Code 登录。客户端确认邮箱和组织后，Cage 将同一身份归入同一张账号卡片，沿用已有的编号、备注和调度设置。登录 Cage 工作台的账户单独管理。

卡片分别显示 Code 和 Desktop 的授权状态。首次使用另一个客户端时，它可能需要单独授权。成功归档后即可手动选择账号，想让调度器也使用它，再开启卡片上的“参与自动分配”。

在工作台「设置 → 通用」里可以关闭默认开启的“使用无痕标签页登录 Claude”。开启时，每次授权从独立的浏览器会话开始，完成后客户端继续保存自己的登录。设置对下次授权生效。

官方客户端启动时会筛除管理用环境变量，状态栏、登录回调和手机渠道只接收运行所需的信息。账户、凭据、历史和项目保留原位；配置和辅助程序通过临时引用访问。客户端仍拥有正常的终端和项目访问能力，这些处理无法保证供应商不能识别运行环境。

## 在 Linux 工作台并排使用两个 Desktop

安装 Claude Desktop 后，展开侧栏的“Claude Desktop”，点“新建 Desktop”。选择所属账号，或选“在此实例中登录”，再点“打开 Desktop”。一个账号保留一份实例。再次打开会回到已有窗口；关闭后重开会继续使用原资料。“默认 Desktop”保留原有环境的桌面。

先打开一个实例，再点另一行的“并排打开”，可左右分屏。屏幕图标里的数字是所属账号编号。关闭某一栏的实例会释放其资源。

每个编号有自己的 Desktop 数据目录、密钥环和授权浏览器。Desktop 首次登录须在对应窗口完成。成功归档的 Code 登录使用该账号自己的配置目录。账号仍引用普通终端的默认登录时，其编号 Desktop 会使用单独的 Code 配置。编号实例目前支持画面和键鼠操作，使用环境内的文件选择器。默认 Desktop 的本机文件桥、音频和系统剪贴板尚未按编号接入。

在“Claude 账号管理”找到对应编号，展开“账号出口”，选择已导入并应用的代理节点。该账号下次打开的 Claude Code、编号 Desktop 和授权浏览器都会使用这个节点，DNS 查询也走同一出口。两个编号可以选择不同节点；实际公网 IP 由各节点的上游决定。选择“跟随环境出口”可恢复默认设置。

切换前请关闭该账号的终端和 Desktop，并等待正在执行的手机任务结束。节点离线、被移除或未通过出口检查时，该账号的连接会被阻止。旧版已设好的手动网络会保留，选择节点后即可改用自动配置。

## 为 Claude Code 终端选账号

点项目旁的“新建终端”，选“Claude 终端”。在“启动账号”选一个已添加的账号，或选“在此终端登录”。多个终端可使用同一账号。若选择的账号还需要授权，先完成授权，再继续打开原项目。若在已有终端用 `/login` 换号，同用这份登录资料的其他终端会暂停，并保留原账号和历史。

“额度用尽后自动接续”单独决定这个会话能否换账号。手选账号时默认关闭。开启后，该终端仍从指定账号开始，符合接续条件时才会切换。选择“自动选择账号”时，Cage 按调度设置选择起始账号。

普通终端中登录的默认 Claude 身份也会被识别。Linux 中，Cage 会尝试将刚识别出的文件登录保存到独立目录，并让官方 CLI 复核身份。使用钥匙串或无法独立保存时，账号继续引用环境的默认登录。终端换号后，需要重新授权才能继续使用原身份。通过“添加账号”或“在此终端登录”可直接建立独立登录资料。

## 自动分配什么时候发生

新终端选“自动选择账号”时使用“调度设置”中选择的方式。

- **均衡分配**：考虑正在使用的终端数量和已知剩余额度，条件相近时轮转，并兼顾同一项目近期使用的账号。
- **按列表顺序优先**：优先使用排在前面的可用账号，相关额度已耗尽、登录失效或暂停分配时使用后面的账号。通过“上移”调整顺序。

关闭某个账号的“参与自动分配”，只影响以后新建的终端，正在使用该账号的任务可以继续。改变调度模式不改变已有会话的账号绑定。

## 共享技能、指令和记忆

登录凭据各自独立，Cage 会话列表统一展示历史。项目文件、项目中的指令与技能直接共用；用户级的本地技能、指令、规则和代理定义共用环境内的资料，同一个项目的自动记忆使用同一位置。更换账号后可以继续使用这些资料。主机系统的个人配置不会自动导入。

从 Claude.ai 账号或组织下载的技能仍属于原账号；登录身份、凭据、账号远程设置和 MCP 的账号授权不自动合并。原有资料同名且内容不同时，Cage 保留原文件并提示先核对，避免覆盖用户资料。

## 在同一会话中换账号

先在账号卡片中填写“接续分组”，将允许接收同一份会话历史的账号设为同一组。未分组的账号不进行跨账号接续。工作资料与个人资料不应随意混入同一组；分组控制自动交接的目标，不构成文件系统安全隔离。

电脑终端上方和手机会话中的账号按钮显示当前绑定。展开后可以选择：

- **每次询问**：由用户选择目标账号，勾选允许交接历史，再执行“切换并恢复历史”。
- **额度耗尽后自动接续**：官方 CLI 报告限流且额度读数确认窗口耗尽时，尝试在同组可用账号间接续。
- **始终等待原账号**：自动接续保持关闭，仍可手动发起一次明确确认的切换。

账号设置中的授权默认只影响新会话；会话内可以单独修改。接续保留同一个 Cage 会话入口，目标账号运行新的官方 CLI 进程并恢复历史，原历史保留。手动切换默认只恢复历史；需要继续执行时，勾选“恢复后继续未完成的任务”。跨账号的服务端提示缓存可能重建，第一轮可能更慢。

交接前必须停止原执行者。执行中的工具、未处理消息、工具审批、后台任务或结果不明的工具会阻止切换；按提示结束或核对后重试。交接失败时可以重试原操作，准备阶段也可取消并保留原账号。Cage 不会为恢复重新提交旧消息或已完成的工具，但模型后续仍可能决定再次调用工具，需要继续检查任务结果。

这套能力运行环境中的原版 Claude Code，不提取订阅令牌代理模型请求。

跨账号恢复、共享资料和授权检查已通过隔离官方 CLI 验证，测试使用合成账号与本地模型响应。真实双订阅服务端兼容性，以及供应商对自动轮换的具体许可仍须核实。CLI 版本或组织策略不支持 Channels 时，手机接续能力也会受到限制。旧额度、服务过载或未知错误不会被当作已确认的额度耗尽。

## 查看五小时和七天额度

打开面板会向环境内的官方 Claude Code 查询五小时、七天用量与重置时间。卡片的“检查状态”可以立即刷新，无需先发一条模型消息。

某个额度窗口没有返回读数时，界面会说明结果，并保留该窗口上次的百分比和读取时间。旧读数不能视为实时可用额度，也不能代表服务一定接受下一条请求。

## 无账号可分配时

按以下顺序检查：账号是否成功登录、是否开启参与分配、是否已达到已知额度、预计重置时间是否已到。先点“检查状态”，身份失效时按提示重新登录。

普通终端切换过账号时，检查新身份是否单独加入调度。官方授权或请求失败，继续查[Claude 登录与账号异常](troubleshooting.md#claude-登录与账号异常)。

## 查看 Token 活动与曲线

打开“设置 → 账户”，在头像与用户名下方查看 Claude Code 与 Desktop Code 的年度热力图，以及每日、每周和累计曲线。选择年份、模型、日志来源、运行入口和统计口径；点击热力格可查看当天的 Token 与请求数，聚焦后用方向键移动日期。下拉选项在页面内展开。

统计覆盖当前运行环境中的默认配置和 Cage 托管账号配置，包含标准日志中的主会话与子任务。Desktop Code 和明确标识为 Cowork 的记录可一同汇总；Cowork 单独目录、未保存的会话或云端数据不会主动导入。自定义配置目录、CCS 配置、其他设备、Claude 网页与 Desktop 普通聊天暂不覆盖。日志来源表示记录所在的配置目录，不能据此认定实际扣费账号；跨配置重复的历史归入“来源不明”。

“按运行入口分布”显示所选年份和筛选条件下，各入口的 Token 数、占比和请求数。可区分 Claude Code 终端、Desktop Code、Cowork、IDE 扩展、SDK／自动化、远程入口等；点击某行可筛选该入口。“运行入口”表示日志记录的请求发起入口，不代表实际执行机器或服务器。每条记录独立分类，不能用现在打开的客户端推断旧请求的入口。

缺少或无法识别入口标识，以及同一请求在复制的历史中出现冲突标识时，都归入“未知入口”。升级后会重读仍保留的日志补分类，已采集计数继续保留；原日志已删除的历史无法补分类，继续显示为未知。普通聊天目前没有接入可靠的本地 Token 明细，不会按文字长度估算或与 Code 用量混算。

“全部 Token”相加输入、输出、缓存读取和缓存写入四类计数。缓存读取也会产生较大的 Token 数；总量不能直接换算成订阅剩余额度或实际费用。五小时、七天额度仍在“Claude 账号管理”中查看。

日期采用运行环境的本地时区，工作台显示统计使用的时区。每日曲线为无记录日期留空，每周曲线汇总该周已有记录，累计曲线汇总所选年份内已记录的用量。无记录可能来自未使用、日志被删除、关闭了会话保存或采集缺口，不能视为已确认的零用量。

本地统计默认启用。工作台运行、环境就绪且 Cage 已解锁时，约每分钟读取一次；点击“刷新统计”可立即读取。首次读取会补读仍保留的历史，大量日志会分批处理。重复记录、流式更新和复制的历史不会重复累加。已经采集的计数独立保留，上游自动清理日志后仍可查看；尚未采集就被删除的历史无法恢复。

统计只保存必要的时间、模型、日志来源、入口分类、计数与哈希去重标识，不另存对话正文、代码或密钥，也不为统计调用模型。运行环境内保存去重计数，工作台保存按日汇总；使用自己的远端环境时，数据通过已有受信连接传回工作台，不发送到外部统计平台。统计文件受系统权限保护，不包含在诊断包中。

展开“统计范围与隐私”，可暂停采集或清除统计。暂停后保留已有计数，重新启用会补读仍存在的日志。清除需要环境就绪，清除后仅统计新请求；原始会话、登录和项目保留。如果清除时连接中断，工作台会保留清除起点，恢复连接后重试，不会重新导入清除前的历史。
