## 从本机代理软件导入

首次安装的代理页，以及本机“设置 → 网络与代理”，会自动查找当前用户配置目录里的 Clash Verge Rev、Clash Neo、Clash Party（原 Mihomo Party）、Clash Nyanpasu、Clash Verge、Clash/ClashX、Mihomo、FlClash、SS/SSR 配置，以及 macOS 上的 ClashX Meta（`~/.config/clash.meta`）与 Surge 配置。找到后会显示软件名称、配置名称和可导入节点数。点击“导入此配置”，再在下方选出口、点击“应用代理”。无需启动原软件，也无需填写它的本地端口。

Cage 会复制节点及认证参数，由内置核心独立连接；原软件的配置、分组、分流规则、系统代理和监听端口保持原样。Clash Verge 的订阅记录如果带有 HTTPS 链接，也会保留，可在 Cage 的“订阅”页手动更新；导入本身读取本地副本，不下载订阅。当前生效配置会包含已缓存的 provider 节点；未缓存或不兼容的节点会提示，Cage 不执行原软件的配置脚本。Clash Neo 的 `nexo` 和 Clash Verge Ninja 的 `ninja` 是这些客户端专用核心的私有协议，随附的标准 Mihomo 核心无法解析，这类节点会在预览和导入结果中列为跳过并说明原因；请向服务商获取同一出口的标准 Mihomo 兼容节点后再导入。

Surge 配置读取 `[Proxy]` 和 `[Proxy Group]` 中的节点，跟随同目录下的本地 `#!include`，`underlying-proxy` 会转成代理链。远程 `#!include` 不会下载，相关节点需在 Surge 中导出完整配置后再导入；WireGuard、Snell v4 及以上、使用钥匙串私钥的 SSH、非 Shadowsocks 的 ShadowTLS，以及链到多成员分组的节点，会在预览中列为未导入。

自动查找限于软件常用的数据目录。如果检测到 `FlClash for oixCloud` 等使用 `age` 加密保存的配置文件，Cage 不会解密私有配置，会在列表中标出客户端名称及不可直接导入的原因；请先从原软件或服务商导出含节点的明文 Clash/Mihomo 配置，再通过“添加来源”导入或手动添加节点。Windows 上的 SakuraCat（`%APPDATA%\SakuraCat\SakuraCat`）以私有格式保存配置，Cage 只会在列表中标出它并说明迁移方法：通过 SakuraCat 支持的导出入口或服务商用户中心取得个人 Clash/Mihomo 订阅、YAML 或节点分享链接，再通过“添加来源”导入；它的本机代理端口不能直接作为节点。便携版、自定义目录或其他格式同样可通过“添加来源”导入。远程连接不读取服务器上的代理软件配置；请手动上传要使用的配置。

## 导入自己的代理

入口是首页“配置网络与代理”，或“设置 → 网络与代理”。点击“添加来源”，选择导入方式：

| 来源 | 怎么填 |
| --- | --- |
| 订阅链接 | 输入名称和 HTTPS 节点订阅地址。首次没有可用节点时，可明确勾选“通过主机网络下载这份订阅”。 |
| 节点配置 | 拖入或点击选择导出的 YAML、YML、JSON 文件（单个不超过 8 MiB），也可粘贴 Clash/Mihomo YAML 或每行一个的节点分享链接。读取后可编辑，点击“导入并验证”完成导入。 |
| 手动节点 | 选择 HTTP、SOCKS5 或 SSH，填写服务器、端口和认证信息。SSH 默认端口为 22，用户名必填；可选择密码或私钥认证。私钥认证须粘贴完整私钥内容，加密私钥还需填写私钥口令。 |

点击“导入并验证”，进入“节点”，选最终出口，再点“应用代理”。本地导入的来源（本地 YAML、粘贴内容、手动节点）可在“订阅”页点编辑：粘贴或选择新的 YAML 后保存会原地更新这个来源，名称不变的节点保留节点选择、代理链与逐节点出口规则；更新会移除当前出口或中转时拒绝更新并保留原配置。同一编辑页可修改某个节点的服务器和端口，认证信息与协议参数不变，修改后仍需重新通过出口检查。订阅链接来源的节点由服务商决定，不能在 Cage 中改地址，请更新订阅。“节点”页的“测速”会对当前列表每次并发 4 个节点测量延迟，失败的节点悬停可查看原因（未载入核心、测速超时或上游失败）；测完后出现“选用最快”，它只把最快节点设为待应用的出口，仍需点“应用代理”才会切换并重新检查网络。“保存设置”用于其他设置，不能替代应用代理。未应用的选择只是草稿。

“导入并验证”检查节点格式和核心配置，成功后仍需验证实际连接与出口：

1. 应用节点后，在“设置 → 网络与代理”点击“验证出口”。该检查通过所选代理发起真实 HTTPS 请求，确认能取得出口 IP 和位置，并与预期出口核对；主机上其他代理客户端能够访问外网，不能代替这一步。
2. 启动工作环境，查看底部网络状态及检查结果。宿主、环境终端和浏览器的出口采样及其他关键检查通过后，才会显示“已联网”。失败项的处理见[为什么应用了节点仍然离线](#为什么应用了节点仍然离线)。

订阅或本地配置可以是含 `proxies` 或 `payload` 节点的 Clash/Mihomo YAML，也可以是每行一条的分享链接列表或其 Base64 编码（v2rayN 风格订阅）。本地导入可以直接粘贴一条或多条分享链接，来源名称留空时使用“本地导入”。支持的分享链接：

| 协议 | 链接格式 | 说明 |
| --- | --- | --- |
| Trojan | `trojan://密码@服务器:端口?sni=…#名称` | 支持 `sni`/`peer`、`allowInsecure`、`alpn`、`fp`，传输 `tcp`、`ws`、`grpc`、`h2` |
| VLESS | `vless://UUID@服务器:端口?security=tls\|reality…#名称` | 支持 `flow`、`sni`、`fp`、`pbk`/`sid`（Reality）及同上传输；`encryption` 非 `none`、`xhttp`、`kcp`、`quic` 暂不支持 |
| VMess | `vmess://Base64(v2rayN JSON)` | 支持 `tcp`、`ws`、`grpc`、`h2` 与 TLS |
| Shadowsocks | `ss://Base64(方法:密码)@服务器:端口#名称`（SIP002）或旧式整段 Base64 | 插件只支持 `obfs-local`/`simple-obfs` |
| Hysteria2 | `hysteria2://` 或 `hy2://认证@服务器:端口?sni=…&obfs=salamander…#名称` | 支持 `insecure`、`mport`、`pinSHA256` |
| TUIC | `tuic://UUID:密码@服务器:端口?congestion_control=…#名称` | TUIC v4 token 链接暂不支持 |
| AnyTLS | `anytls://密码@服务器:端口?sni=…#名称` | 支持 `insecure`、`fp`、`alpn` |

无法无歧义转换的链接（其他协议、未支持的传输方式或伪装头、缺少端口或凭据等）不会被静默丢弃，会和名称一起列在来源的跳过原因中；跳过原因不包含链接内容或凭据。Xray/v2rayN 原生 JSON 与只引用远程 provider 的配置仍不支持。导入采用支持的节点、代理链及节点域名解析设置，不采用订阅中的主机系统代理、TUN、监听端口或直连规则。同一份配置中 `type: inline` 的 provider 节点会一并导入；设置了 `override` 或过滤规则的 inline provider 会列在跳过原因中。节点的 `dialer-proxy` 指向只含一个本来源节点的分组时，按该节点导入代理链；分组含多个节点、`DIRECT`、`use` 或过滤规则时仍会跳过该节点。

普通节点参数保留并交给 Cage 随附的 Mihomo 核心校验。例如，从 FlClash 复制的 VLESS 节点可以保留 `xudp: true`，无需手动改成其他字段。内核可能忽略未知字段；配置校验通过后，仍需应用节点并检查实际出口。环境公网 UDP 的阻断规则不受这些协议选项影响。

VMess、VLESS 和 Trojan 的 WebSocket 节点可以导入旧字段 `ws-path`、`ws-headers`。节点须明确设置 `network: ws`，Cage 会将路径和请求头转换为 `ws-opts.path`、`ws-opts.headers`，已保存的旧节点在应用代理时也会转换。新旧字段可同时存在，路径须一致，请求头按名称合并并忽略名称的字母大小写。相同请求头的值冲突、字段写法重复或旧字段用于其他传输方式时，来源会显示具体原因，需要修改该节点后重新导入。

Hysteria2 节点可使用 `mport` 指定端口跳跃范围、`pinSHA256` 指定证书指纹，导入时会转换为核心支持的字段并保留功能。若节点使用不支持的协议、引用本机文件或网卡、管理字段重复、别名参数冲突或代理链不可用，会跳过该节点，并在来源下显示导入数量、跳过数量和原因。点击「查看原因」可展开具体节点；依赖失败节点的代理链也会跳过。若所有节点均被跳过，导入失败；更新影响当前出口或中转节点时保留原配置，请先应用其他节点再更新。其余节点还须整体通过核心配置校验，校验失败时原配置保持不变，可在设置的「日志与诊断」中导出诊断包查看校验记录。

手动添加 SSH 节点时，可在“服务器公钥”中填写可信公钥，每行一条；留空时不校验服务器身份。

SSH 节点（`type: ssh`）可以把自己的 VPS 直接作为固定出口，服务器上只需开启 SSH，无需另外部署代理服务。可用 `password` 或 `private-key` 认证；`private-key` 须直接填写 PEM 私钥内容（含 `-----BEGIN ... PRIVATE KEY-----`），引用本机私钥文件路径的节点会被跳过，加密私钥可配合 `private-key-passphrase`。建议用 `host-key` 固定服务器公钥（`ssh-keyscan` 输出中的 `ssh-ed25519 AAAA...` 部分），未填写时核心不校验服务器身份。未写 `host-key-algorithms` 时，Cage 按所填公钥的类型限定协商算法，服务器同时启用多种主机密钥时也会使用你固定的那一种；显式写了 `host-key-algorithms` 则按你写的为准。SSH 节点仅转发 TCP。示例：

```yaml
proxies:
  - name: my-vps
    type: ssh
    server: 203.0.113.10
    port: 22
    username: root
    private-key: |
      -----BEGIN OPENSSH PRIVATE KEY-----
      ...
      -----END OPENSSH PRIVATE KEY-----
    host-key:
      - "ssh-ed25519 AAAA..."
```

同一个订阅地址可能按请求的客户端身份返回不同格式。Cage 下载时使用 Clash 客户端身份，服务商返回 YAML 时可以导入；返回 Base64 或分享链接列表时按上面的分享链接规则导入。

Clash/Mihomo YAML 中的 `dns.proxy-server-nameserver` 会按可用项随来源保存，最多采用 4 个远程 HTTPS DoH 地址（支持域名形式）；其中的非 HTTPS、本机/内网地址、含用户名密码、带 `#` 参数（如 `#skip-cert-verify=true`、`#DIRECT`）或超出上限的条目会被忽略，不会阻断节点导入或订阅更新，未采用自定义地址时回退到 Cage 自身的“节点域名解析”设置。它们仅解析该来源中具体节点的服务器域名；业务 DNS、订阅下载和其他来源继续使用各自的设置，解析服务自身的域名由 Cage 的“节点域名解析”设置引导解析。订阅更新会同步替换或移除这份列表，已导入的订阅需更新一次才能取得该设置。从本机客户端导入时也会按同样规则保留可用列表。Cage 不采用订阅的业务 DNS、DNS 监听端口、hosts 或全局 DNS 匹配规则。

内置核心按域名区分节点解析服务。多个来源使用同一节点域名且指定不同 DNS 时，导入、更新或应用会报错并保留原配置；可统一这些来源的节点 DNS，或移除冲突来源。

## 把原客户端的代理链迁到 Cage

如果旧配置显示“代理链需要迁移”，先在原客户端查看实际经过的节点。例如，v2rayN 监听的 `127.0.0.1:10808` 只能把流量交给 v2rayN，无法告诉 Cage 最终走哪个出口。Cage 会停用这类节点，保留旧配置供对照。

1. 在 v2rayN 选中原链里的中转和最终出口，使用“导出分享链接至剪贴板（多选）”，在 Cage 的迁移提示中点“导入节点”，填写来源名称，每行粘贴一个链接，再点“导入并验证”。也可以从“添加来源 → 节点配置”进入。使用 Clash 时，可从已有代理软件导入包含具体节点的配置，或导入 Clash/Mihomo YAML。若原链中的某一跳无法导入，请取得该跳的兼容节点配置后继续。
2. 打开“节点”。只有一个远程节点时，选择“单节点”。原来通过中转连接住宅代理时，选择“链式代理”，依次选中转和住宅出口，核对预览为 `Cage → 中转节点 → 住宅出口`。
3. 点击“应用代理”，再点“验证出口”，核对 IP 和地区。启动环境后，确认底部网络状态为“已联网”。账号如果单独绑定了旧的本机节点，也需要重新选择可用节点。

手动填写时，“服务器”一栏应填代理服务提供的远程节点地址。例如，下面的地址和端口需替换成服务商提供的值，有认证要求时一并填写：

```yaml
proxies:
  - name: 住宅出口
    type: socks5
    server: proxy.example.com
    port: 1080
```

## 通过中转连接住宅出口

如果住宅节点无法直接连接，在“节点”页切换到“链式代理”。按连接顺序选择中转，将住宅节点设为“最终出口”；需要多次中转时点“添加中转”。节点可以来自不同来源。

应用前检查预览，例如：`Cage → 中转节点 → 住宅代理 → 目标网站`。目标网站看到的是最终出口。订阅更新不会覆盖已保存的组合；使用中的节点被移除时会保留原配置并显示错误，需要你重新选择。

## 为什么应用了节点仍然离线

代理核心就绪和工作环境获准联网是两个步骤。环境启动后先保持业务外网关闭，执行出口、DNS、系统与浏览器配置、共享目录、宿主管理接口和网络阻断等关键检查。DNS 项同时要求解析器只指向环境内地址，且到公共 DNS 的 UDP/53、TCP/53 与 DoT/853 直连未绕过网关；宿主管理接口项还探测链路本地元数据地址和已配置的用户代理端口。IPv6 项要求环境的全局 IPv6 地址为零，并核对路由或拒绝记录。缺少探针结果时显示未知；任一关键项失败或证据缺失都会继续关闭外网。

macOS 主机只从 `networksetup` 报告的硬件端口中选择具有可用 IPv4 地址的物理出口；`utun`、`bridge`、`vmen`、`vmenet`、`vmnet`、`tap`、`lima`、`awdl`、`llw`、`p2p`、`gif`、`stf`、`anpi`、`ap` 等隧道、桥接和虚拟机接口即使带有地址或默认路由，也不会被绑定为代理出口。

Windows 主机只选择带可用 IPv4 和默认路由的硬件网卡；VPN、TUN、虚拟机 NAT 等虚拟网卡不会被选中。物理网卡桥接到 Hyper-V 外部虚拟交换机时，物理网卡本身没有 IPv4，Cage 改用与它 MAC 地址相同、带 IPv4 默认路由的管理用 `vEthernet` 网卡。若主机没有可用的硬件 IPv4 网卡或同 MAC 孪生网卡（例如物理口直通或独享给 Hyper-V 软路由虚拟机），Cage 会回退接受带有效单播 MAC、首选 IPv4 与默认路由的宿主 Hyper-V 虚拟以太网适配器（`Hyper-V Virtual Ethernet Adapter`）；未配置默认路由的 `Default Switch` 以及 TUN、VPN、TAP 等其他虚拟网卡仍会被排除。

如果直连节点使用 Tailscale 私网地址（`100.64.0.0/10`、`fd7a:115c:a1e0::/48`）或主机另一张网卡直连私网网段中的地址，Cage 会仅将该节点绑定到主机路由所指向的对应网卡（例如 Windows 的 `Tailscale`、macOS 的 `utun*`、Linux 的 `tailscale0`），同时保持 DNS 和公网代理节点继续绑定在物理网卡上。通过 `dialer-proxy` 中转的后跳节点不会改绑本机网卡。

出口检测通过所选代理读取公网 IPv4 地址，按顺序覆盖多家独立网络与运营商服务：`https://ipv4.icanhazip.com/`、`https://checkip.amazonaws.com/`、`https://whatismyip.akamai.com/`、`https://1.1.1.1/cdn-cgi/trace`（只读取响应中的 `ip=` 行）、`https://api.ipify.org/` 和 `https://ipv4.geojs.io/v1/ip`。前一个服务失败时立即改用下一个；前一个服务 1 秒内没有结果时，下一个服务同时开始，取第一个有效的公网 IPv4。所有请求都只经所选代理发出，只带 Go 默认的 User-Agent，不附加 Cookie、凭据或其他自定义头。双栈节点使用其 IPv4 出口完成检查；当前所选链路（含前置节点）中有节点的服务器为纯 IPv6 字面量地址时，内置代理核心才在顶层开启 IPv6，以便经主机 IPv6 连接该代理服务器；这一开关作用于整个核心，开启期间域名形式的节点服务器也可能解析到 IPv6 地址并经主机 IPv6 连接。未选用的节点（包括仅供账号专用节点使用的节点）不会开启它，因此纯 IPv6 字面量节点只能在被选为环境出口或位于所选链路上时连接。核心 `dns.ipv6` 始终为 `false`，客机 IPv6 阻断与 IPv4 出口规则不变。宿主、环境终端和浏览器使用相同的检测方式。启动检查无法取得有效地址时，业务外网保持关闭，可稍后重试或检查节点。所有检测服务都超时时，Cage 会再经同一代理请求一次节点延迟测试所用的 `https://www.gstatic.com/generate_204`，只用于区分原因：返回 204 时提示节点出口可能按域名屏蔽了检测服务，可更换节点或请代理服务商放行上述任一检测地址；同样超时时提示节点可能无法连通，需检查节点地址、端口、账号密码和本机到节点的网络。这次请求的结果不会当作出口地址，也不会放开外网。

点击底部网络状态查看失败项，修复后重新检查。核心运行但环境未启动时会显示“待启动环境”。关键检查通过、联网授权有效时才显示“已联网”。

“出口采样不完整”会列出未取得结果的路径：宿主、虚拟机终端或浏览器，以及超时、检测通道返回的 HTTP 状态或缺少地址等原因。终端代理检查通过只证明该次终端采样成功，宿主和浏览器仍须分别取得结果。动态 IP 规则决定哪些出口地址可以接受，采样失败时仍须重新检测。

浏览器的出口采样没有响应或返回 HTTP 503 时，Cage 会等待一秒并重试一次。重试期间外网保持关闭；持续失败时保留最后一次检测结果。浏览器配置不符或响应缺少出口地址时，须先处理对应失败项。环境已经就绪、仅联网检查未通过时，页面会显示“环境已启动，联网检查未通过”，可直接重检网络。

离线时仍可使用终端、共享文件及环境内的本地服务。浏览器地址栏中的 `localhost` 指当前 Cage 环境；开发服务应在 Cage 终端里启动。

## 系统镜像的下载网络

系统镜像使用主机网络下载，与 Cage 环境的代理节点分开。Clash 等软件只开启“系统代理”也可以接管这些下载，无需开启 TUN；下载连接不绑定物理网卡，也不会修改代理软件的节点或规则。下载网站若被主机代理规则设为直连，Cage 遵循该规则；主机未配置代理时使用直连。

- macOS：读取系统 HTTP、HTTPS、SOCKS 代理及 PAC，每次请求和重定向按目标地址解析。
- Windows：读取当前用户的系统代理；PAC 与自动检测通过 WinHTTP 按目标地址解析。
- Linux：支持代理环境变量、GNOME 手动桌面代理及主机 TUN。此构建遇到 GNOME 自动 PAC 会停止并提示改用 TUN 或代理环境变量；其他桌面环境请设置代理环境变量或开启 TUN。

从终端启动时，目标协议对应的 `HTTP_PROXY`、`HTTPS_PROXY` 优先于系统设置，`ALL_PROXY` 作为缺省代理，并遵循对应的 `NO_PROXY` 例外。这些主机设置不会传入环境。代理连不上或已配置的 PAC 解析失败时，下载停止，不因失败切换直连；修复主机代理后，在初始化界面继续安装，已有下载会尝试续传。

系统镜像和开发工具优先使用官方源。Debian 镜像下载失败后尝试提供同一固定版本的国内镜像；Debian 软件源和 Linux 工具在官方源不可用时尝试备用镜像。各下载路径保留原有的摘要、软件包签名或应用签名检查，自定义 Debian 软件源保持原样。

环境内的进程和在环境内下载的开发工具继续走 Cage 的独立代理。系统镜像下载成功不代表网络检查通过，进入工作台仍需完成环境的网络与隔离检查。

## 时区、语言与出口规则

在“设置 → 时区与语言”选择跟随出口或手动设置。自动模式通过代理查询出口位置，不使用主机位置替代。位置服务失败时可重试或切换节点；手动设置时区和语言仍须确认出口国家或地区。

网络页的“IP 变化规则”按最终出口节点保存，支持静态 IP，以及动态 IP 的同一城市、同一州／省、同一国家／地区或不限地区。城市模式还检查国家与州省。切换最终出口时自动恢复该节点的规则；首次使用的节点沿用当前的静态或动态模式及允许范围，通过代理检测并确认非中国大陆出口后绑定自己的 IP 或地区。仅更换中转、刷新订阅、重新检查或重启会保留该节点的基准。

例如，住宅节点001与节点003分别绑定各自的固定 IP，来回切换会自动使用对应地址；同一住宅节点意外更换 IP 时仍会暂停外网，需要确认后明确修改。旧配置未记录出口基准所属的节点时，原规则持续生效，直到明确应用节点后为其检测并建立绑定。

中国大陆出口禁止放行。检测地址命中内置大陆网段库，或定位结果为中国大陆时，业务外网保持关闭；静态 IP 和“不限地区”均不能豁免。无法确认出口国家或地区时也保持关闭，离线终端和文件仍可使用。地区定位和网段库可能存在误差；后台按周期采样，无法保证第三方代理每条连接都使用同一出口。

保存影响系统环境的配置可能要求重启。先保存文件；运行中不会因后台发现位置变化而静默重启任务。

## 暂停、恢复和网络切换

点击底部状态可手动暂停外网。暂停会切断已有外部连接，保留本地任务和文件操作；关闭、重开 Cage 或刷新订阅不会解除手动暂停。

后台会定期核对出口与环境配置。所有出口检测服务均超时时，Cage 在现有联网许可到期前继续重试，不延长许可；到期仍未确认时关闭外网，并尝试完整复检。发现出口或环境配置不符合规则时立即暂停。主机切换网络后会尝试恢复并完整复检；原先人为暂停的状态仍需主动恢复。控制服务失联后，已有网络授权到期关闭。固定出口还需要代理服务本身保证，周期采样不能证明所有连接都走同一 IP。

自动完整复检首次在 15 秒后尝试，失败后依次等待 30、60、120、240 秒，之后每次等待 300 秒；实际开始时间还取决于环境就绪、当前操作和内存压力。网络状态会显示剩余等待时间或等待原因。重新检查必须取得全部关键证据，自动恢复不会修改已保存的出口规则。

## DNS 与诊断

业务 DNS 通过所选代理转发。入口在“设置 → 网络与代理”：

| 设置 | 默认 | 用途 |
| --- | --- | --- |
| 加密 DNS | `https://1.1.1.1/dns-query` | 环境内的业务 DNS、联网检查中的 DNS 项和内置核心自身的解析器都使用它，经所选节点发出。 |
| 备用加密 DNS | 空 | 每行一个 HTTPS DoH 地址，最多 4 个。主端点连接失败、返回 429 或 5xx 时按顺序改用下一个，同样经所选节点发出；最近一次成功的端点优先使用，避免每次查询都等待被阻断的端点超时；改用备用端点后每隔 5 分钟让一次查询先回试主端点，主端点恢复后重新优先使用，不会因一次偶发失败长期停留在备用端点或公共 DNS 上。 |
| 公共 DNS 备用 | 关闭 | 开启后在以上端点之后追加 Google 公共 DNS `https://8.8.8.8/dns-query`。 |
| 节点域名解析 | `https://1.1.1.1/dns-query`、`https://223.5.5.5/dns-query` | 经主机网络解析节点服务器域名和主机网络下载。只接受数字 IP 的 DoH 地址，因为这一步没有其他解析器。加密 DNS 或备用端点填写域名时，该域名也由这里的服务经主机网络解析（不经所选节点），因此这些服务商会看到该 DoH 域名。 |

联网检查、客机 DNS 与内置核心读取同一组端点，不会出现检查用一个端点、实际解析用另一个端点的情况。所有端点都不可用时，错误提示会列出端点主机名并指向上述设置；不显示端点路径，因为部分服务把个人解析器 ID 放在路径里。

保存以上任一 DNS 设置时，运行中的环境会重启；内置代理核心在环境启动时一并改用新的加密 DNS、备用端点和节点域名解析，与环境业务 DNS 和联网检查保持一致，不需要另外重新应用节点。

公共 DNS 备用默认关闭：开启后，当你设置的端点经节点不可用时，环境内的域名查询会发给第二家服务商，换取可用性；如果你选择某个 DoH 是为了只让一家服务商看到查询，请保持关闭，改为在“备用加密 DNS”中填写你信任的端点。备用端点与节点域名解析保存在配置目录的 `dns.json`，与主配置分开，旧版本读取主配置不受影响；回退到旧版本时这些附加设置不生效。

如果所选代理出口会在安装或工具下载阶段中断 `curl` 的 TLS 1.3 握手，可在“设置 → 网络与代理”中显式开启“安装与工具下载兼容模式（限制 curl 最高使用 TLS 1.2）”。该开关默认关闭，仅作用于环境安装、工具更新和组件下载时的临时 `curl` 调用，不改变正常浏览、对话和 API 连接的 TLS 版本。

出口位置默认只查询 ipwho.is、IP.SB、ipwhois.app、GeoJS 和 ipapi.co 五家服务。若它们经你的节点都不可用，可在“设置 → 网络与代理”中显式开启“出口位置查询备用服务 ipinfo.io”。该开关默认关闭，与安装兼容模式互相独立；开启后，仅在五家都失败时，经所选节点向第三方 ipinfo.io 发送已测得的出口 IP（请求 `https://ipinfo.io/<出口IP>/json`，不带账户、Cookie 或项目标识），换取国家或地区与时区。它的结果只用于国家级判断：州、省和城市留空，不会据此绑定或判定州、省、城市范围，这类规则在只有 ipinfo.io 结果时仍保持外网关闭。账号专用节点的出口核对也遵循同一开关。

节点域名的启动解析属于准备通信，与环境业务 DNS 分开。Cage 不修改主机系统代理或 TUN，也不改变本机其他代理软件的节点。

代理页“诊断”可检查核心状态、重启 Cage 核心或选择独立监听端口。端口占用时选择未占用端口即可，修改后按提示重启环境。具体症状见[故障排查](troubleshooting.md#节点已应用但无法联网)。

### VLESS REALITY 握手失败

从 V2rayN 等客户端迁入 VLESS + TCP + REALITY 节点后，可能出现配置校验通过、真实 HTTPS 请求失败，核心日志报 `REALITY authentication failed` 的情况。先逐项对照原客户端与服务端参数，包括服务器、端口、UUID、传输方式、SNI、客户端指纹、flow、公钥和 short-id；配置语法正确仍可能存在握手兼容问题。

参数核对一致后，可按 [Mihomo 官方 TLS 文档](https://wiki.metacubex.one/config/proxies/tls/#reality-optssupport-x25519mlkem768)检查 `reality-opts.support-x25519mlkem768`，该选项用于支持 X25519-MLKEM768 密钥交换。对于需要此兼容选项的节点，在该节点现有的 `reality-opts` 中保留原公钥和 short-id，并添加：

```yaml
reality-opts:
  public-key: <原节点公钥>
  short-id: <原节点 short-id>
  support-x25519mlkem768: true
```

这是节点内的配置片段，需放回完整的 Clash/Mihomo YAML 后重新导入、应用。保留原配置，每次只调整这一项，再重复相同的 HTTPS 与出口检查。部分节点在启用此项后可以恢复连接；请按原节点与服务端要求使用，不要对所有 REALITY 节点无条件添加或重写参数。若仍失败，保留日志继续排查，不能仅凭该错误判断服务端版本或设置，也不要通过关闭证书校验、放宽出口规则或启用直连回退处理。

### TLS 节点无 client-fingerprint 时握手超时

部分 VMess、VLESS、Trojan 等开启 `tls: true`（常见于 `network: grpc` 等 TCP 类传输）且**未设置 `client-fingerprint`** 的节点，在较旧版本 Mihomo（如 Go 1.22 构建的 v1.18.x）上可正常连通，但在 Cage 内置的 Go 1.26 构建的 Mihomo（v1.19.33 及以上）上会出现核心日志持续报 `connect error: context deadline exceeded`、出口探测全部超时且外网保持关闭的情况。

这是因为 Go 1.26 默认在 TLS 握手中携带后量子密钥交换（X25519MLKEM768），导致 ClientHello 报文体积更大，部分节点服务端或中间链路会将其丢弃。设置中的「TLS ClientHello 分段传输兼容模式」作用于代理隧道内的目标网站 HTTPS 握手，不会改写内置核心连接外层代理节点时的 TLS 指纹。

遇到该现象时，可在导入的 Clash/Mihomo YAML 中仅对受影响节点显式补充：

```yaml
client-fingerprint: safari
```

若 `safari` 仍不适用，可改试 `firefox`（部分链路下 `chrome` 与 `random` 仍可能触发相同的大 ClientHello 丢包问题）。保存修改后在代理页刷新或重新导入该来源并重新应用节点，再重新运行出口探测与完整网络检查，确认出口 IP 与全部关键检查均通过。请仅按需为受影响节点添加，不要批量改写所有节点，也不要通过关闭证书校验、放宽出口规则或启用直连回退绕过。

## 通过 Tailscale 私网使用 SSH

从侧栏「浏览器」下方打开「Tailscale」，在 Cage 浏览器授权后，可让本机与 Cage 环境通过私网双向 SSH。连接步骤、公钥和本机 SSH 服务要求见 [Tailscale 与 SSH 私网](tailscale.md)。

私网访问由用户主动启用，并受设备和 SSH 授权约束。外层通信继续经过 Cage 受控出口，暂停外网或代理中断会影响连接。这个入口与默认阻断的主机、局域网直连分别处理，不开放主机公网监听或子网路由。
